The default engine remains IPM. engine(simplex) uses the numerical primary
and bounded original-data certificates for benevolent/aggressive selection.
It requires at most 16 variables after free-variable splitting and 32 selected
observations. Individual zero quantities/columns are allowed; each selected
DMU requires a positive input and output.

The secondary uses the original exact primary optimal face. Numerical self
is preserved; a rounded score is not a new exact RHS. Recovered points must
pass original-data checks and existing export/self consistency checks.
A failed secondary retains primary weights. An exact feasible point and
improving recession direction prove unboundedness; missing numerical values
or an unverified basis do not prove infeasibility.

Each LP shares 16 exact exchanges,80 million integer-operation work units,
10 million per check and 128 limbs. The auxiliary LP may use 17 variables.
Unsupported/resource-limited attempts retain unknown/fallback. These limits
differ from numerical simplex iterations. Terminal ray inspection uses
remaining work after unsuccessful recovery and has no extra exchanges.
Primary-basis acceleration experiments are excluded.

With matrix, primary_recovery_diagnostics and secondary_recovery_diagnostics
have 31 columns; see help for names and status/reason/stop definitions. Rows
follow selected observation order. computation_diagnostics gives original
observation numbers for joining raw DMU IDs and variable flags.
Per-LP total_steps=original+eq+aux+final<=16;
total_ops=initial+ray+eq+aux+final. Summary counters aggregate both stages.
Integer counters exclude numerical LP,ordinary matrix work and final double
export; they do not measure elapsed time. Ten counters and diagnostic_version
6201 are returned without matrix. detail prints stage/path/cost summaries.
Native uses not_evaluated_native scope and does not load the certificate engine
on a cold call. Normalization-loss diagnostics observe positive-to-zero
conversion without altering solver inputs or recovering lost quantities.
Internal exact optimality,rounded weights and numerical self are distinct.

The legacy VRS peer formula and secondary surrogates are unchanged.
vrscross(limzhu) requires input VRS and changes the peer formula,not the
secondary objective. Missing ratios remain missing; means use available peers.
See help for self/peer maverick and diagonal conventions.

Native numerical warnings (1.6.1)
Both native LP stages check finite coefficient/RHS arrays before optimizer
setup. A skipped primary remains unavailable; a skipped secondary retains
primary weights. The command continues other evaluators and warns about
missing weights/partial peer means. detail identifies original observations;
matrix returns native_numerical_diagnostics (see help for codes).
has_numerical_warning and the two n_native_nonfinite_* counts are available
without matrix. numerical_diagnostic_version is6601; the existing certificate
diagnostic_version remains6201. Simplex native-state columns are missing.
No new solution-recovery policy or tolerance/engine switch is introduced.
Zero warnings is not an exact optimality certificate. This guard cannot
remove global-scaling loss or make out-of-range normalized weights finite.

    python tests/test_crosseff_preflight.py --stata /path/to/stata-mp --output /new/output

Intended peer objectives (1.7.0)
Exclude the evaluator before summing. Simplex uses exact original binary64
peer sums for bounded certificates, including rounded numerical proposals.
Native remains numerical-only and warns when objective representation is
rounded or loses terms; failed secondary solves retain primary fallback.
The two branches do not promise identical selected weights. The primary
score, surrogate definitions, peer-ratio conventions and existing6201/6601
schemas are preserved. New objective diagnostics use7001. See help and
tests/CROSSEFF_OBJECTIVE.txt. Install the complete current 92-file ado/
bundle, including all nine cross-efficiency helpers listed above.

Optional optimal-face diagnostics (1.8.0)
Add optimadiag to retain the original DEA output and independently diagnose
F1/F2 actual weight multiplicity and legacy peer denominators. The new helper
must be installed before requesting the option. Cold default IPM without the
option still does not load the simplex/exact helper stack. See help for
dimensions, work limits, unsupported/unknown states and stored-weight linkage.
optimadiag alone does not compute CE ranges. Add cerange for bounded
cellwise CE ranges. Mean/rank ranges and a new weight selection policy
remain separate work.
Run the self-contained example below after installing all80 runtime/help files.

Optional CE ranges (1.9.0)
Add cerange (implies optimadiag). Diagnostic schema is7701; the unchanged
weight-diagnostic schema is7301. CE helper core readiness7601 and adapter7701
must be installed together with the updated optima adapter7701. Both native
engines use this independent bounded exact path. Limits:32observations,
inputs+outputs+2*VRS<=15; legacy peer formula only. Unsupported/unknown and
unavailable F2 states never substitute a different face. Returned bounds use
positive denominators; cutoff availability is separate. Read endpoint/display
and stored-weight link states. No mean/rank range or automatic weight choice.

Failure-only raw recovery (1.10.0)
Explicit simplex attempts at most two raw-data representations and one bounded
exact primary fit after the original numerical primary fails. Only finite,
raw-checked weights are published. Accepted evaluator weights/self remain
unchanged. Recovered rows use range-safe legacy CRS/VRS or input Lim-Zhu peers.
Existing peer means can change because additional evaluator rows are available.
The LP budgets, native IPM default, peer formulas and selection policy remain
unchanged. matrix returns raw_recovery_diagnostics, raw_scaling_diagnostics
and raw_peer_status; raw summary counters are available without matrix.
Unknown, unbounded, export failure and denominator-policy missing values are
distinct. No missing primary is replaced by a score of one. The raw diagnostic schema
is 8401. Run tests/test_crosseff_raw.py for the portable recovery/peer checks.

Scoped decoder extension (1.10.1)
The failure-only raw primary path accepts finite coefficient magnitudes beyond
the earlier 2^-900 to 2^900 domain, including subnormals. The raw secondary uses
this domain only if its primary model required it. Other certificate and face
diagnostic paths retain their default domain. Existing accepted selections,
LP budgets and all public diagnostic schemas (including raw8401) are preserved.
Resource-limited secondary attempts warn and retain certified primary weights.
Run python -B tests/run.py --suite crosseff_decoder --suite crosseff_raw.

Bounded exact arithmetic (1.10.2)
Selected over-width products and residual checks remove common powers of two
before exact subtraction/division and full-value restoration. The existing
128-limb, work and pivot limits remain unchanged. This can distinguish a finite
secondary optimum from an exact improving ray; an unbounded secondary retains
certified primary weights. Resource-limited unknowns retain their warnings.
The public diagnostic schemas remain unchanged; base certificate readiness is6204.
Use the complete matched ado directory when upgrading, including the main loader.
Run python -B tests/run.py --suite crosseff_dyadic --suite crosseff_raw.
The arithmetic suite generates synthetic integers locally and requires no private
data, Git history, captured logs or user-specific directory edits.

Failed numerical proposals (1.10.3)
After both numerical proposals fail, a valid lossless representation can enter
one bounded exact primary fit. Existing accepted proposals retain their path.
No extra exact-fit retry budget is granted. Unknown secondary results retain
certified primary weights and their warning.

Finite positive inputs can require normalized original-unit weights outside
Stata's finite range. Such weights stay unavailable; this does not establish
mathematical infeasibility. The obstruction flag records a failed conversion,
not a proof about every alternative optimum. Mantissa/exponent or scaled-weight
returns require a separate output contract and are not enabled by this update.

Exact positive objective factors (1.10.4)
A failed raw secondary width check may make one extra bounded attempt after
exact common-factor removal. Mata finds the positive gcd and exact quotients;
original objective units are retained with the normalized certificate. Recovery
path 5 includes this attempt and accumulates prior work and pivots. Finite
certificates still need original-unit export/guard acceptance. An exact ray
retains the certified primary weights. No resource/tolerance limits are raised.

Portable component and linkage checks:

These three suites supplement the existing 36-suite set. Complete validation

Point-export failure diagnostics (1.10.5)
Internal point-export reasons give an existing integer-work/limb/shift refusal
priority over a subsequent conversion failure. Rejected points remain missing;
score acceptance, resource limits and all public diagnostic schemas are unchanged.
Raw helper readiness is8405. Both cross-efficiency and crossgame loaders require
the matched helper. Restart Stata or clear all when upgrading the full directory.

Portable synthetic regression:
    python3 -B tests/run.py --suite crosseff_point --suite crosseff_raw
The point suite generates integer packets locally and includes explicitly
test-only work-limit injection. Limits are restored before a repeated command.
Its rejected packets are not proofs of mathematical LP infeasibility.
